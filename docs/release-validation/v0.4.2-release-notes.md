# v0.4.2 Release Notes

**Status: Draft — not a published release.**

`RELEASE_CANDIDATE_SHA = 50862a352626ea38d2fbb36f2ff0ecfc667266d0`

## Release story

**v0.4.2 makes the existing read-only Architecture Intelligence MCP surface directly consumable by
qualified coding-agent clients without changing architecture semantics.**

Every `v0.4.x` release has kept AIP's Architecture Answer semantics — `get_architecture_drift`,
`get_evidence`, `get_service_dependencies`, their declared-vs-observed qualification model, and their
snapshot-bound evidence — completely stable. `v0.4.2` does not add a fourth tool, change what any tool
returns, or alter what counts as evidence. What it adds is a **negotiated MCP transport mode**
alongside the existing direct-envelope mode, so a mainstream coding-agent MCP client can connect with
its own out-of-the-box negotiation instead of AIP's stricter direct envelope — and then **actually
verifies**, against real client software rather than only a test suite, that this works end to end.

## What changed since `v0.4.1`

- Added a negotiated MCP transport mode (standard `initialize`/session handshake) alongside the
  existing direct-envelope mode, dispatching to the same read-only tools with identical semantics —
  see [`docs/mcp.md`](../mcp.md) and
  [`docs/specifications/0.4.2/i1-dual-mode-mcp-transport.md`](../specifications/0.4.2/i1-dual-mode-mcp-transport.md).
- Added candidate setup guides for Codex CLI, Claude Code, Cursor, and VS Code
  ([`examples/mcp-clients/`](../../examples/mcp-clients/README.md)).
- Two real interoperability defects, found only by qualifying against actual client software (not the
  test suite alone), were fixed before this candidate froze:
  - A negotiated-mode routing gap that let an unbounded direct-marked method reach the SDK and hang
    the server on `subscriptions/listen` (found via Claude Code).
  - An over-strict rejection of a negotiated follow-up missing the `MCP-Protocol-Version` header,
    stricter than both the pinned SDK's own fallback and the MCP specification's own backward-
    compatibility allowance (found via VS Code/GitHub Copilot Chat).

## Boundaries — this release notes file SHALL NOT claim

- All MCP clients are supported. Only the exact client/version combinations in the
  [qualified matrix](v0.4.2-client-qualification.md) are qualified.
- All versions of a qualified client are supported. A different version of a listed client is
  unverified.
- Public-internet MCP security. `/mcp` has no public-internet authentication in `v0.4.2` — local or
  trusted-network use only.
- Authentication or multi-tenancy. Neither exists in this release.
- Stateful sessions. AIP's negotiated mode is stateless; no client tuple required or was qualified for
  stateful session behavior.
- Write capabilities. All three tools remain strictly read-only.
- Generic graph query or transitive dependency analysis. AIP's tools return one-hop declared/observed
  dependency facts for a service, not an open-ended query surface.
- "Desired State" or architecture transformation. AIP never proposes or performs architecture change.
- Agent-generated architecture as truth. An agent's explanation of AIP's output is not itself an
  architecture fact; only AIP's own graph-backed, evidence-qualified answers are.
