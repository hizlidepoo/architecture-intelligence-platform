# `v0.4.2-rc.3` Candidate Preparation — I3.2 re-freeze (second re-freeze)

## Supersedes an invalidated candidate

This record re-freezes `RELEASE_CANDIDATE_SHA` after
[`v0.4.2-rc.2`](v0.4.2-rc.2-candidate-preparation.md)'s candidate
(`6461db6d51ee29e9c973e62b005aa84d5d95c077`) was marked **INVALIDATED**. I3.4's real VS Code
(GitHub Copilot Chat) actual-client qualification run against `6461db6d` found a second
release-blocking transport defect: AIP's negotiated-mode guard hard-rejected any markerless follow-up
request missing an `MCP-Protocol-Version` header. The MCP specification's client-side rule requires a
client to include this header on every follow-up (so VS Code's own omission, observed on
`notifications/initialized`, is not itself spec-conformant), but the spec's *server-side*
backward-compatibility clause separately directs a server that receives no such header to tolerate it
(assume protocol version `2025-03-26`) rather than reject — exactly the allowance the pinned SDK
already implements. AIP's guard honored neither the SDK's own precedent nor that server-side
allowance, so VS Code could not connect to AIP at all under `6461db6d`. Full finding, root-cause
isolation, and sanitized reproduction:
[`docs/release-validation/v0.4.2-client-traces/vscode.md`](v0.4.2-client-traces/vscode.md).
Fix: [ADR 0014's second "Amendment" section](../adr/0014-negotiated-mcp-client-interoperability.md)
(PR #150) — a missing header on a markerless follow-up is now forwarded to the pinned SDK instead of
rejected; a markerless follow-up whose header is *present* and names the direct/single-exchange
`2026-07-28` era remains rejected (a genuine contradiction, not an absence).

Per spec §4.4, this again touches `app/mcp/guard.py` ("MCP transport implementation"), a
candidate-affecting change — hence this second fresh freeze and full automated gate re-verification
rather than an evidence-only rebind.

`docs/specifications/0.4.2/i1-completion-record.md` is rebound to this candidate as part of this same
re-verification (a genuine re-run, not a citation-only update — see that record's own "Candidate
binding" note).
