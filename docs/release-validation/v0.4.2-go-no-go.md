## Known limitations

- Cursor's and VS Code's protocol-qualification evidence is client UI evidence (relayed chat
  transcripts and, for VS Code, an info-level MCP output-channel log), not a raw network capture —
  Codex CLI's and Claude Code's evidence additionally includes passive network capture or direct
  session-transcript extraction. This tier difference is stated explicitly in each trace, not implied
  away.
- Cursor's qualifying cycle and its Appendix A.2 UX observation ran on two separately-`--serve`d
  fixture instances (the first was torn down between them for unrelated operational reasons); both
  instances independently show `revision_after == revision_before`, but this is not one continuous
  session — documented explicitly in `cursor.md`.
- VS Code's reconnect call used a different observation window than its qualifying attempt (Copilot
  Chat defaulted to "today" rather than the demo window, since it was not told one for that specific
  call) — a valid, well-formed response under spec §6.11 (which requires only tool discovery plus one
  successful read-only call at reconnect, not the qualifying window or the §6.9 deterministic result),
  not a semantic mismatch.
- `/mcp` has no public-internet authentication in `v0.4.2` — local/trusted-network use only, as in
  every prior release. No new limitation introduced by I3.

None of the above is a release blocker; each is a scoped, explicitly documented evidence-tier or
environment detail, not a gap in what was actually verified.
